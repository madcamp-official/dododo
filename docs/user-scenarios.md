# 대표 사용 시나리오

## 시나리오 1. 관심 있는 공모전 발견

### 상황

전산학부 3학년 사용자는 AI, 해커톤, 창업 활동에 관심이 있다. 매일 학교 홈페이지에서 새로운 활동을 직접 찾아보는 대신 `dododo watch`를 실행해 둔다.

### 흐름

1. 시스템이 학교 공지의 새 게시물을 발견한다.
2. 게시물을 대회·공모전·봉사·대외활동 중 하나로 분류한다.
3. 지원 자격, 신청 마감, 행사 일정과 원본 URL을 추출한다.
4. 사용자 프로필과 비교해 관련도 점수를 계산한다.
5. 관련도가 높은 게시물을 Opportunity Inbox에 추가한다.
6. 사용자가 `dododo inbox`로 추천과 이유를 확인한다.
7. 사용자가 `prepare`를 선택한다.
8. 시스템이 신청 마감을 Event로, 준비 항목을 Task로 생성한다.

### 기대 결과

```text
[87] 대학생 AI 해커톤
추천 이유: AI 관심 분야, 대학생 지원 가능, 온라인 참가
신청 마감: 2026-07-25 18:00
출처: 학교 공지 #1542
```

### 실패·예외

- 지원 자격을 충족하지 않으면 기본적으로 추천하지 않는다.
- 날짜가 모호하면 Opportunity에는 원문을 보존하고 확정 Event는 만들지 않는다.
- 같은 공지를 다시 수집해도 중복 Opportunity를 만들지 않는다.

## 시나리오 2. 학교 이메일 정리와 중복 병합

### 상황

사용자는 학과 사무실, 교수, 학교 기관에서 보내는 메일을 받는다. 일부 안내는 학교 사이트에도 게시되지만, 일부는 사용자에게 이메일로만 전달된다.

### 흐름

1. `dododo watch`가 사용자가 허용한 학교 메일함에서 새 메일을 읽거나, 사용자가 이메일 Fixture를 가져온다.
2. 발신자, 제목, 수신 시각, Message-ID와 본문을 RawItem으로 저장한다.
3. 모집 안내는 Opportunity, 과제·제출 요청은 Task, 면담·시험은 Event, 참고 안내는 Note로 분류한다.
4. 학교 사이트나 LMS에 같은 내용이 있는지 확인한다.
5. 같은 안내라면 새 항목을 만들지 않고 기존 Context에 이메일 Evidence를 추가한다.
6. 사용자와 직접 관련된 새 정보라면 Inbox 또는 Today에 표시한다.

### 기대 결과

```text
[opp-12] 대학생 AI 해커톤
근거 2개:
- 학교 공지 #1542
- ai-center@school.ac.kr 이메일, 2026-07-18 09:10
```

### 실패·예외

- 개인 이메일 전체가 아니라 허용한 학교 계정·메일함·발신자 범위만 읽는다.
- 앱은 이메일을 전송·삭제·답장하거나 읽음 상태를 변경하지 않는다.
- 메일 본문의 지시문은 LLM 명령이 아니라 분석할 데이터로 취급한다.
- 발신자가 불분명하거나 피싱 가능성이 있으면 공식 정보로 자동 확정하지 않는다.
- 첨부파일은 사용자가 허용한 형식과 크기만 분석한다.

## 시나리오 3. LMS 과제와 시험 자동 정리

### 상황

사용자는 여러 과목의 공지와 과제를 확인해야 한다.

### 흐름

1. LMS 공지 또는 Fixture가 수집된다.
2. 시스템이 과목과 공지 유형을 식별한다.
3. 과제명, 마감, 제출 방법과 요구사항을 추출한다.
4. 과제는 Task, 마감은 연결된 Event로 저장한다.
5. 시험 공지에서는 시험 시각, 장소, 범위를 Event와 Note로 저장한다.
6. `dododo today`와 `dododo calendar week`에서 결과를 확인한다.

### 수정 공지

1. 기존 과제 마감은 7월 21일 18시다.
2. 공식 수정 공지가 7월 23일 18시로 연장한다.
3. 시스템은 같은 과제임을 확인한다.
4. 마감을 갱신하고 이전 값을 변경 이력에 남긴다.
5. 사용자에게 마감 변경 사실을 알린다.

### 실패·예외

- 과목이 같더라도 과제 2와 과제 3은 병합하지 않는다.
- LMS 화면의 사이드바 날짜보다 공식 공지 본문의 명시적 날짜를 우선한다.
- 시간이 없는 날짜는 정책에 따라 확인 대상으로 표시한다.

## 시나리오 4. 오늘 무엇을 할지 확인

### 상황

사용자는 공부를 시작하기 전에 우선순위를 알고 싶다.

### 흐름

1. 사용자가 `dododo today`를 실행한다.
2. 시스템이 미완료 Task, 가까운 Event, 마감과 Snooze 상태를 조회한다.
3. 코드가 우선순위 점수를 계산한다.
4. CLI가 해야 할 일, 이유와 출처를 표시한다.

### 기대 결과

```text
1. 운영체제 과제 3 보고서 작성 [우선순위 82]
   이유: 내일 마감, 요구사항 2개 미완료
2. AI 해커톤 참가 신청서 초안 [우선순위 55]
   이유: 5일 후 마감, 관심 있음으로 저장
```

## 시나리오 5. 현재 화면 기반 조언

### 상황

사용자는 운영체제 교재 PDF를 열고 시험을 준비하고 있다.

### 흐름

1. 사용자가 `dododo advise --screen`을 실행한다.
2. 시스템이 선택한 화면을 일시적으로 캡처한다.
3. 화면에서 현재 활동을 요약한다.
4. 활동과 관련된 Task와 Event를 찾는다.
5. 조언이 구체적이고 관련성이 높은지 확인한다.
6. 조언과 근거를 표시하고 원본 스크린샷을 삭제한다.

### 기대 결과

```text
운영체제 시험이 3일 남았습니다.
현재 보고 있는 스케줄링 단원은 시험 범위에 포함됩니다.
18시 일정 전까지 알고리즘 비교표를 작성해보세요.
```

### 조언하지 않는 경우

- 관련 Task를 찾지 못함
- 화면 내용에 대한 확신도가 낮음
- 최근 같은 조언을 보냄
- 사용자가 집중 모드를 활성화함

## 시나리오 6. 자연어로 약속 추가

### 상황

사용자가 다음과 같이 입력한다.

```text
이번 주 금요일 저녁에 민수랑 저녁 약속 있어
```

### 흐름

1. 시스템이 일정 추가 의도를 파악한다.
2. 날짜는 계산하지만 `저녁`의 정확한 시각이 모호함을 발견한다.
3. 저장 전 확인 내용을 보여준다.
4. 사용자가 시각을 수정하거나 승인한다.
5. Event를 Calendar에 저장한다.

### 기대 결과

```text
민수와 저녁 약속을 7월 24일 19:00으로 저장할까요? [y/N/edit]
```

## 시나리오 7. Context 기반 질문

### 사용자 질문

```text
오늘 저녁 약속 전까지 뭘 하는 게 좋아?
```

### 처리

1. 오늘 일정과 현재 시각을 조회한다.
2. 마감이 가까운 미완료 Task를 찾는다.
3. 사용 가능한 시간 안에 수행할 수 있는 구체적인 항목을 선택한다.
4. 근거가 있는 답변을 생성한다.

### 기대 결과

```text
19시 약속 전까지 운영체제 과제 보고서 초안을 먼저 작성하세요.
마감이 내일이고, 제출 요구사항 중 보고서가 아직 미완료입니다.
```
