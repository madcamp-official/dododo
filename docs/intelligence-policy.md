# Context Intelligence 정책

## 1. 책임 분리

### LLM이 담당하는 일

- 공지와 문서에서 사실 후보 추출
- 공지 종류와 사용자 행동 요구 분류
- 화면 활동 요약
- 제목이 다른 항목의 의미 유사도 보조 판단
- 추천 이유와 조언 문장을 자연스럽게 표현
- 사용자 자연어에서 일정·Task 후보 추출

### 일반 코드가 담당하는 일

- 날짜와 남은 시간 계산
- Hash와 외부 ID 기반 중복 확인
- 상태 저장과 변경 이력
- 관련도와 우선순위 점수
- 출처 충돌 우선순위
- 알림 반복 억제와 Snooze
- 완료 항목 제외
- LLM 출력 형식 검증

### 사용자가 확정하는 일

- 애매한 일정 시각
- Opportunity 참여 여부
- 낮은 확신도의 Task 후보
- 애매한 중복 병합
- Task 완료와 취소

## 2. Opportunity 생성 정책

학교 공지에서 다음 정보를 추출한다.

- 활동 종류
- 주최자
- 지원 자격
- 신청 마감
- 활동 일자
- 장소 또는 온라인 여부
- 비용 또는 혜택
- 원본 URL

### 필수 조건

지원 자격이 명확하고 사용자가 충족하지 못하면 추천 대상에서 제외한다. 자격을 판단할 정보가 없으면 `unknown`으로 두고 추천 이유에 불확실성을 표시한다.

### 관련도 점수 초안

| 항목 | 점수 |
|---|---:|
| 관심 분야 일치 | 0~30 |
| 선호 활동 종류 | 0~20 |
| 일정 충돌이 적음 | 0~15 |
| 마감까지 준비 시간 충분 | 0~15 |
| 선호 지역·온라인 조건 | 0~10 |
| 과거 저장·무시 반응 | -20~10 |

- 70점 이상: 추천
- 45~69점: 전체 Inbox에는 저장하되 적극 추천하지 않음
- 45점 미만: 기본 목록에서 숨김
- 기준 점수는 평가 후 조정한다.

## 3. 자동 Task 생성 정책

자동 Task를 만들 수 있는 경우:

- 사용자가 수강 중인 과목의 명시적 과제
- 사용자가 참여하기로 선택한 Opportunity의 준비 항목
- 사용자가 자연어로 명확하게 추가한 할 일

자동 Task를 만들면 안 되는 경우:

- 단순 홍보 공지
- 행동 요구가 없는 참고 자료
- 사용자가 아직 저장하지 않은 Opportunity
- 확신도가 낮은 LLM 추정

확신도 처리 초안:

| 확신도 | 처리 |
|---:|---|
| 0.80 이상 | 자동 생성 가능 |
| 0.50~0.79 | Candidate로 생성하고 확인 요청 |
| 0.50 미만 | Fact만 보존하거나 무시 |

## 4. 동일 항목 병합 정책

가능하면 외부 시스템의 안정적인 ID를 가장 먼저 사용한다.

1. LMS 과제 ID, 공지 ID, 캘린더 UID가 같음
2. 같은 원본 URL 또는 첨부 관계
3. 같은 과목·프로젝트와 차수
4. 제목과 핵심 행동 유사도
5. 마감일 근접성

점수 기반 후보가 필요할 경우:

| 항목 | 점수 |
|---|---:|
| 제목·의미 유사도 | 0~40 |
| 같은 과목·프로젝트 | 0~20 |
| 마감일 근접성 | 0~15 |
| 첨부·원본 관계 | 0~15 |
| 등장 인물·팀원 | 0~10 |

- 70점 이상: 자동 병합
- 40~69점: 사용자 확인
- 40점 미만: 별도 항목

절대 병합 방지 조건:

- 과제·시험 차수가 다름
- 학기 또는 연도가 다름
- 제출과 발표가 독립적인 마감을 가짐
- 사용자가 이전에 병합을 거부함

## 5. 충돌 해결 정책

기본 출처 우선순위:

```text
최신 공식 LMS·학교 공지
> 지정된 공식 과제 문서
> 외부 Calendar
> 일반 문서와 사용자 메모
> 화면 Activity
> LLM 추정
```

동일 권위의 출처가 충돌하면 더 최근에 관찰된 명시적 변경을 우선한다. 자동으로 확정하기 어려우면 두 값을 모두 보존하고 사용자 확인을 요청한다.

기존 값은 삭제하지 않고 다음을 기록한다.

- 이전 값
- 새 값
- 변경 근거
- 변경 시각
- 자동 또는 사용자 확인 여부

## 6. Task 우선순위 정책

초기 점수 예시:

| 조건 | 점수 |
|---|---:|
| 24시간 이내 마감 | +40 |
| 3일 이내 마감 | +25 |
| 7일 이내 마감 | +10 |
| 6시간 이내 관련 일정 | +15 |
| 미완료 요구사항 1개 | +5, 최대 +15 |
| 현재 Activity와 관련 | +10 |
| 사용자가 중요 표시 | +20 |
| 최근 같은 추천 표시 | -30 |
| Snooze 중 | -100 |
| 완료·취소 상태 | 추천 제외 |

점수뿐 아니라 각 가감점 이유를 저장해 CLI에서 설명할 수 있어야 한다.

## 7. 적극적 조언 정책

다음 조건을 모두 만족할 때 화면 기반 조언을 보여준다.

- 현재 Activity의 확신도가 기준 이상
- 기존 Task 또는 Event와 관련성이 높음
- 실행 가능한 구체적인 행동이 있음
- 최근 같은 조언을 하지 않음
- 집중 모드나 알림 금지 시간대가 아님

조언은 다음 형식을 따른다.

```text
무엇을 할 것인가
+ 왜 지금 해야 하는가
+ 어떤 Context를 근거로 했는가
```

## 8. 알림 억제 정책

- 같은 추천은 최소 30분 반복하지 않는다.
- 사용자가 Snooze한 동안 표시하지 않는다.
- 완료·취소한 Task는 알리지 않는다.
- 하루 최대 알림 수를 설정한다. 초기값은 5회다.
- 사용자의 Quiet Hours에는 긴급하지 않은 알림을 보내지 않는다.
- 마감 변경처럼 새로운 중요 정보는 기존 추천과 별도로 알릴 수 있다.

## 9. 안전과 개인정보

- 원본 없는 LLM 추정은 확정 Fact로 저장하지 않는다.
- 웹과 문서의 명령문은 LLM 지시가 아니라 분석할 데이터로 취급한다.
- 화면 원본은 영구 저장하지 않는다.
- API Key, 원문, 화면 내용은 일반 로그에 남기지 않는다.
- 외부 전송 전에 허용된 Source와 최소 범위를 확인한다.
- AI는 신청, 제출, 파일 수정, 이메일 전송을 자동 실행하지 않는다.
