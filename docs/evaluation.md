# 평가 계획

## 1. 평가 목적

이 프로젝트는 기능 개수보다 Context를 정확히 정리하고 유용한 추천을 제공하는지를 평가한다.

핵심 질문:

1. 공지와 LMS에서 필요한 사실을 정확히 추출하는가?
2. 관심 기회와 의무적인 Task를 올바르게 구분하는가?
3. 같은 항목을 중복 생성하지 않고 변경을 반영하는가?
4. 사용자에게 관련 있는 Opportunity를 상위에 추천하는가?
5. 추천이 구체적이고 근거가 있는가?

## 2. 평가 데이터셋

### 초기 최소 구성

| 데이터 | 최소 개수 | 포함할 사례 |
|---|---:|---|
| 학교 공지 | 20 | 관련·비관련 활동, 자격 미충족, 마감 없음 |
| LMS 공지 | 15 | 과제, 시험, 수정, 취소, 일반 공지 |
| 사용자 발화 | 15 | 일정 추가, Task 추가, 모호한 날짜, 질문 |
| 화면 Activity | 8 | 공부, 과제, 무관한 화면, 낮은 확신도 |
| 다중 출처 묶음 | 10 | 같은 Task, 비슷하지만 다른 Task, 충돌 |

모든 입력에는 사람이 직접 작성한 기대 결과를 연결한다.

## 3. 핵심 지표

### Fact 추출

- Task·Opportunity·Event 분류 정확도
- 마감일 Exact Match
- 요구사항 Precision과 Recall
- Evidence 연결 비율

### 병합과 변경 반영

- 동일 항목 병합 정확도
- 서로 다른 항목의 잘못된 병합 비율
- 반복 동기화 후 중복 생성 수
- 수정 공지 반영 정확도

### Opportunity 추천

- Precision@5: 상위 5개 중 사용자가 관련 있다고 평가한 비율
- 자격 미충족 공지 노출 비율
- 추천 이유의 사실 일치율

### Task 추천

- 완료·Snooze 항목 잘못 추천 비율
- 중복 추천 비율
- 추천에 Evidence가 있는 비율
- 사용자가 `useful`로 평가한 비율

## 4. 비교 실험

### Baseline

각 공지를 독립적으로 LLM에 보내 요약하고, 출처 간 병합이나 코드 기반 점수 없이 결과를 나열한다.

### Proposed

Fact 추출, ContextItem 분류, 출처 간 병합, 사용자 프로필 관련도, 코드 기반 우선순위와 Evidence 정책을 적용한다.

비교할 항목:

- 중복 Task 수
- 마감 변경 반영 여부
- 관련 공지 상위 추천 정확도
- 추천 근거 제공 여부
- 동일 입력 반복 시 결과 일관성

## 5. 대표 회귀 테스트

### 공모전

- AI에 관심 있는 사용자에게 AI 해커톤 추천
- 지원 학년이 맞지 않으면 추천 제외
- 같은 공지 재수집 시 Opportunity 하나만 유지

### LMS

- 과제 공지에서 Task와 마감 Event 생성
- 일반 수업 공지는 자동 Task로 만들지 않음
- 과제 2와 과제 3을 병합하지 않음
- 수정 공지로 마감 갱신
- 이전 마감과 근거 보존

### 일정 대화

- 명확한 일정은 확인 후 저장
- `저녁`처럼 모호한 시각은 확인 요청
- 이미 존재하는 동일 약속은 중복 경고

### 화면 조언

- 현재 공부 단원과 시험 범위를 연결
- 관련 Task가 없으면 억지 조언하지 않음
- 같은 조언을 반복하지 않음

## 6. 데모 체크리스트

- [ ] 네트워크 실패 시 사용할 Fixture가 준비되어 있다.
- [ ] LLM 호출 실패 시 기본 결과 또는 명확한 오류가 나온다.
- [ ] 빈 DB에서 Setup부터 전체 시나리오가 실행된다.
- [ ] 잘못된 병합 사례가 재현되지 않는다.
- [ ] 모든 결과에서 `evidence` 명령이 작동한다.
- [ ] 화면 원본이 디스크에 남지 않는 것을 확인한다.
- [ ] 데모 결과와 Benchmark 수치를 README에 기록한다.
