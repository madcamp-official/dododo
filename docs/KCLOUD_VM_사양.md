# KCLOUD VM 사양

> 확인 기준: 2026-07-10 11:55 (KST)

`dododo` CLI와 로컬 LLM(Ollama) 서버를 함께 띄울 KCloud VM의 하드웨어 사양이다. 실제 학교 사이트·이메일·LMS 연동, SQLite, 화면 캡처, 로컬 LLM 호출을 이 VM에서 검증한다.

## dododo 로컬 LLM(Ollama) 운영 참고

`.env.example`의 `DODODO_LLM_BASE_URL=http://localhost:11434`는 이 VM에 직접 띄운 Ollama 서버를 가리킨다는 전제다. 모델은 중국계(Qwen 등)를 제외하고 Google Gemma 3로 정했다(선택 근거는 `.env.example` 주석과 관련 PR 참고).

| 모델 | 용도 | VRAM(24 GiB) 안에서의 여유 |
|---|---|---|
| `gemma3:12b` (`DODODO_TEXT_MODEL`) | 학교 공지·이메일 등 긴 한국어 문서에서 구조화 Fact 추출(JSON Schema 강제 출력) | Q4 양자화 기준 여유 있음 |
| `gemma3:4b` (`DODODO_VISION_MODEL`) | 3~5분 주기로 도는 화면 활동 요약처럼 짧고 빈번한 호출 | `gemma3:12b`와 동시에 로드해도 여유 있음 |

- 두 모델을 동시에 올려도 24 GiB 안에서 여유가 있다는 것은 대략적인 추정이며, 실제 동시 로드·동시 요청 시 VRAM 사용량은 이 VM에서 직접 확인이 필요하다(아래 "추가 확인이 필요한 항목" 참고).
- 화면 캡처 원본 이미지는 요약 생성 즉시 삭제하는 정책(`AGENTS.md`의 개인정보와 사용자 통제)이라 디스크에 누적되지 않는다 — 루트 디스크 97 GiB에서 이 부분이 지속적으로 자라날 걱정은 없다.
- SQLite Context DB(`DODODO_DB_PATH=./data/context.db`)와 로그는 같은 97 GiB 루트 디스크를 함께 쓴다. MVP 규모(Fixture 수십 개, 실 연동 1개 학교 기준)에서는 여유가 충분하지만, 정식 운영 단계로 넘어가면 별도 볼륨 분리 여부를 재검토한다.

## 추가 확인이 필요한 항목

제공된 출력만으로는 다음 사양을 확인할 수 없다.

- 운영체제와 커널 버전
- 디스크의 실제 물리 매체 종류
- 네트워크 대역폭 및 공인 IP
- Ollama 설치 여부·버전과 `gemma3:12b`/`gemma3:4b` 실제 동시 로드 시 VRAM·응답 지연
- 학교 공지 사이트·이메일 실 연동 시 예상 트래픽과 방화벽/아웃바운드 정책
