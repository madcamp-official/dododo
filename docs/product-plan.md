# 프로젝트 기획안

## 1. 프로젝트 정의

### 프로젝트명

`dododo` — 대학생용 Local-first Context Assistant

### 한 줄 설명

학교 사이트, 학교 이메일, LMS, 일정, 로컬 문서, 현재 화면과 사용자 대화를 하나의 로컬 Context로 정리하고, 해야 할 일과 관심 기회를 근거와 함께 알려주는 CLI 기반 AI 비서.

### 해결하려는 문제

대학생의 정보는 여러 장소에 흩어져 있다.

- 학교 홈페이지에는 공모전·봉사·대외활동 공지가 있다.
- 학교 이메일에는 학과·교수·기관이 보낸 공지, 모집 안내, 과제 변경과 개인에게만 전달된 정보가 있다.
- LMS에는 수업 공지·과제·시험 일정이 있다.
- PDF와 로컬 파일에는 공부해야 할 내용과 과제 요구사항이 있다.
- 캘린더에는 수업 외 일정과 약속이 있다.
- 현재 화면에는 사용자가 실제로 무엇을 하고 있는지가 나타난다.

사용자는 매일 이 정보를 직접 확인하고, 나와 관련 있는지 판단하고, 메모하고, 일정과 할 일로 다시 옮긴다. `dododo`는 이 반복 작업을 줄이고 흩어진 정보를 최신의 일관된 Context로 유지한다.

## 2. 목표 사용자

첫 번째 목표 사용자는 다음과 같은 대학생이다.

- 여러 수업의 과제와 시험을 동시에 관리한다.
- 공모전·해커톤·봉사·대외활동 공지를 자주 확인한다.
- PDF, 브라우저, AI 도구를 오가며 공부하거나 과제를 수행한다.
- 일정을 캘린더에 꼼꼼히 옮기는 일을 번거롭게 느낀다.
- 중요한 정보를 놓치지 않되 불필요한 알림은 원하지 않는다.

MVP에서는 학교·LMS·이메일 시스템이 다른 모든 대학을 지원하지 않는다. 데모 대상 학교 사이트 1곳, LMS 1종, 학교 이메일 계정 또는 이메일 Fixture 1종을 기준으로 검증한다.

## 3. 핵심 가치

### 흩어진 정보를 하나로 정리한다

공지, 과제, 시험, 개인 일정과 현재 활동을 별도 정보로 남겨두지 않고 서로 연결한다.

### 관심과 의무를 구분한다

추천받은 공모전은 `Opportunity`, 반드시 제출할 과제는 `Task`, 시험과 약속은 `Event`로 구분한다.

### 판단 근거를 보여준다

모든 Task와 Recommendation에서 원본 공지 URL, 이메일 Message-ID·발신자, LMS 공지, 파일 위치 또는 화면 요약을 확인할 수 있어야 한다.

### 사용자의 통제권을 유지한다

시스템은 조언하고 정리하지만, 애매한 일정 확정이나 외부 신청·제출 같은 행동은 사용자 확인 없이 실행하지 않는다.

### 필요한 정보만 외부로 보낸다

원본 Context는 로컬에 저장하고, 외부 LLM에는 판단에 필요한 최소 내용만 전송한다.

## 4. 제품의 핵심 질문

> 서로 다른 출처에서 반복·충돌·변경되는 대학생의 정보를 어떻게 Opportunity, Task, Event로 정리하고 적절한 시점에 근거 있는 행동을 추천할 수 있는가?

## 5. 핵심 가설

1. 공지를 단순 요약하는 것보다 사용자 프로필과 일정으로 관련도를 계산하면 더 유용한 공지를 추천할 수 있다.
2. 학교 사이트와 이메일에 중복 게시된 안내를 하나로 병합하면 같은 활동이나 마감이 여러 번 생성되는 문제를 줄일 수 있다.
3. LMS와 학교 이메일을 Task와 Event로 구조화하면 과제와 시험 일정을 놓치는 비율을 줄일 수 있다.
4. 현재 화면을 기존 Context와 연결하면 일반적인 조언보다 구체적인 다음 행동을 제안할 수 있다.
5. LLM이 모든 판단을 수행하는 방식보다, 코드가 상태·우선순위·알림 정책을 담당하는 방식이 더 일관되고 설명 가능하다.

## 6. 제품 원칙

- 원본 없는 판단을 만들지 않는다.
- 이메일은 사용자가 허용한 계정·폴더·발신자 범위만 읽고, 전송·삭제·답장을 수행하지 않는다.
- 관심 기회와 확정된 할 일을 자동으로 혼동하지 않는다.
- 화면 관찰만으로 완료 상태를 확정하지 않는다.
- 모호한 날짜와 시간은 확인 후 저장한다.
- 사용자가 무시하거나 미룬 항목을 반복해서 방해하지 않는다.
- 한 번의 LLM 호출로 수집·병합·추천을 모두 처리하지 않는다.
- 데모가 가능한 하나의 완성된 흐름을 기능 개수보다 우선한다.

## 7. MVP 결과물

- Windows/macOS에서 실행 가능한 CLI
- 로컬 Context SQLite DB
- 학교 사이트, 학교 이메일, LMS Fixture 또는 실제 대상 Connector
- Opportunity Inbox, Task 목록, Calendar 목록
- 자연어 일정 추가와 Context 질문
- 선택한 화면 기반 수동 조언
- 근거 확인과 사용자 피드백
- 평가 Fixture와 Benchmark 결과
